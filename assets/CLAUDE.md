# Project Collaboration Guide

- Read this file, the CCB policy and the relevant role brief before acting.
- Keep changes small, scoped and reversible. Preserve existing user work.
- Run the narrowest relevant validation before reporting completion.
- Do not push, deploy, merge or rewrite Git history without explicit human approval.
- Record durable project facts in the shared or role-specific CCB memory instead of relying on chat history.

## Completion standard

A task is complete only when its requested change is implemented, the relevant validation has
passed, and any remaining risk or follow-up is clearly reported.
