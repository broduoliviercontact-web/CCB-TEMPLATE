# Graph analysis

1. Locate entry points, callers, dependencies and tests.
2. Trace the smallest evidence-backed path through the affected components.
3. Report impact, constraints and uncertainties with file references.
4. Read the real flow before proposing changes.
5. Name dependencies and impacts without expanding the plan beyond the brief.
6. Do not edit files, review a patch or generate graph output unless asked.
